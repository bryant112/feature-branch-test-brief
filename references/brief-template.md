# Brief Template

Use this structure for feature-branch testing briefs.

## Status Overview
- What is in play right now?
- What should the tester assume is stable versus first-pass?
- Which branch or feature slice is being exercised?

## Testing Targets
- Session or startup behavior
- Core happy path
- Feature-specific behavior
- Cross-feature interaction
- Refresh/update behavior
- Error handling or fallback behavior
- UI clarity or operator workflow

## TODONE
List things that are implemented enough to test now.

## TODO
List the next obvious improvements or incomplete integrations.

## TODONTS
List tempting but wrong directions, unstable assumptions, or behaviors the tester should not rely on.

## TOCANTS
List current technical limits, missing data, or things the system simply cannot do yet.

## Feedback Prompts
Keep prompts short enough to answer by hand:
- What broke?
- What felt fake or unconvincing?
- What confused you?
- Which feature combo was active?
- What should be easier next time?
